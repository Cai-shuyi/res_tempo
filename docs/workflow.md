# 流程

流程分為六個階段。每個階段有明確的輸入、輸出與完成標準。前一階段未完成，不進入下一階段。

```
需求 -> 規格 -> 設計 -> 實作 -> 驗證 -> 交付
```

## 1. 需求（Request）
- **輸入**：目標、資料來源、預期輸出。
- **輸出**：需求摘要，列出範圍內與範圍外的項目。
- **確認點**：人確認範圍。
- **完成標準**：範圍、輸入、輸出都有明確的描述。

## 2. 規格（Spec）
- **輸入**：需求摘要。
- **輸出**：`docs/spec/` 下的規格文件，包括資料格式、欄位與單位、計算公式、流程步驟、QA 規則與門檻。
- **確認點**：人確認公式、單位與門檻。未定的數值以 `null` 標示，不由 Claude 決定。
- **完成標準**：每個計算都有公式；每個欄位都有單位與來源；每個門檻都是已確認的數值或明確標示為待定。

## 3. 設計（Design）
- **輸入**：規格文件。
- **輸出**：模組切分、階段切分、每個階段的輸入與輸出檔案、設定檔結構。
- **確認點**：人確認架構。
- **完成標準**：每個階段都能單獨執行，並且只依賴前一階段的輸出。

## 4. 實作（Implement）
- **輸入**：規格與設計。
- **輸出**：程式碼與對應的設定檔。
- **規則**：
  - 沒有規格的部分不寫。
  - 規格變動時，先更新規格，再改程式。
  - 一次只完成一個階段，不同時改多個階段。
- **完成標準**：程式可編譯，相關設定都從設定檔讀取，沒有寫死的數字。

## 5. 驗證（Verify）
- **輸入**：實作結果。
- **輸出**：測試結果，包括單元測試、階段測試，以及與參考結果的比對。
- **規則**：如果有舊版程式可以對照，新版必須與它比對結果，差異要說明原因。
- **完成標準**：測試全部通過；若有差異，已列出並經人確認。

## 6. 交付（Deliver）
- **輸入**：通過驗證的程式與文件。
- **輸出**：QA 報告、文件同步的更新、提交與合併請求。
- **確認點**：人審查後合併到主分支。
- **完成標準**：文件與程式一致；QA 報告已產生；QA 門檻未定的項目已列出。

## 流程變更
流程本身的變更也要走這套流程：先改這份文件，經人確認後，再套用到專案。
