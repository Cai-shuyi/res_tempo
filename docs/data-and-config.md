# 資料與設定規範

## 資料分層
- **原始資料**：只新增，不覆寫。修改時保留版本紀錄。
- **處理結果**：由程式產生，可以重跑，不進版控。
- **交付結果**：要保留的結果，另外放在 `releases/`，並記錄來源與設定。

## 命名
- 模型或批次資料夾名稱：英文小寫，用底線分隔，例如 `model_a`。
- 檔案名稱中的溫度或條件：固定格式，寫在規格中。
- 欄位名稱：英文，區分大小寫。同一個概念在所有檔案中用同一個名稱。

## 單位
- 每個欄位都要有單位。無單位的欄位（例如比例）要寫明「無單位」。
- 單位未確認時，寫「待確認」，不由 Claude 推定。
- 單位變更要在規格中記錄，並說明換算方式。

## 必要欄位與缺項
- 每種輸入檔案都要列出必要欄位。缺少必要欄位時，程式要報錯，不默默略過。
- 可以缺項的欄位要寫明缺項時的行為，例如「缺少 nrd 時，整個模型不考慮 contact」。
- 缺項的判斷範圍要寫明：每一列各自判斷，或整個模型一起判斷。

## 數值格式
- 設定檔中的科學記號要寫成帶小數點的形式，例如 `1.0e-6`。
- 布林值、空白、null 的意義要在註解中說明。

## 設定檔（`config/`）
- 每個項目都有註解，包括用途、單位、預設值。
- 預設值來源（例如原程式的某行）要寫在註解中。
- 不在設定檔中放密碼、token 或金鑰。
- 設定的分工要寫在規格中：哪個階段讀取哪個區段。

## 版本紀錄
- 每次階段執行都產生 manifest，記錄執行時間、使用的設定、輸入的筆數與結果摘要。
- 要重現結果時，需要的資訊是：設定檔、輸入資料、manifest。
- 設定檔的變更要在 commit 訊息中說明原因。

## 資料中不應該有的東西
- 個人資料或機密資訊。
- 未經確認的數字，不論來源。
