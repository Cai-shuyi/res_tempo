# 文件規範

每種文件有自己的讀者與用途。不要把內容寫進錯的地方，也不要讓兩份文件重複描述同一件事。重複會造成不同步。

## CLAUDE.md
- **讀者**：Claude，每次對話都會載入。
- **內容**：專案目的（一段）、流程指向、工作順序、完成標準、禁止事項、語言要求。
- **不放**：長篇的架構說明、數字表格、已解決的問題紀錄、檔案清單（檔案清單放 README）。
- **長度**：保持精簡。內容多時，用 `@路徑` 指向細節文件。
- **必須同步**：流程或規則改變時，CLAUDE.md 要同步更新。

## README.md
- **讀者**：人。
- **內容**：專案目的、目錄結構、安裝、執行指令、測試指令。
- **不放**：給 Claude 的工作規則。

## 規格文件（`docs/spec/`）
- **讀者**：人與 Claude。
- **內容**：資料格式、欄位與單位、計算公式、流程步驟、QA 規則與門檻。
- **規則**：每個公式都要有來源或確認紀錄。未確認的項目標示為「待定」。

## 設定檔（`config/`）
- **讀者**：程式與人。
- **內容**：參數、初始值、門檻。
- **規則**：
  - 每個項目都要有註解，說明用途、單位、預設值與來源。
  - 程式中不寫死設定檔已經定義的數字。
  - 設定檔中的數字要寫成帶小數點的形式，例如 `1.0e-6`，不要寫 `1e-6`。
  - 門檻未確認時寫 `null`。

## 資料說明（`data/README.md`）
- **讀者**：人與 Claude。
- **內容**：資料分層、檔案格式、必要欄位、缺項規則、輸出檔案與命名。
- **規則**：格式一改，這份文件要同步改。

## Skill（`.claude/skills/<名稱>/SKILL.md`）
- **讀者**：Claude，在任務符合描述時才載入。
- **必要欄位**：`name`、`description`。
- **`description` 寫法**：說明什麼時候使用，例如「當使用者要求 QA 或品質檢查時使用」。不要只寫功能名稱。
- **內容**：輸入、步驟、輸出位置、不要做的事。

## 文件之間的關係
- 規則寫在 CLAUDE.md，細節寫在規格或設定檔，CLAUDE.md 只放指向。
- 同一件事只寫在一個地方；其他地方用連結指過去。
