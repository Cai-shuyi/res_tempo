# 角色與確認點

## 分工原則
- **人**負責決定：公式、單位、門檻數字、範圍、是否改動舊程式、是否合併到主分支。
- **Claude**負責執行：依規格實作、跑測試、同步文件、回報結果。

Claude 不替人做以下決定：
- 填寫未確認的數值或門檻。
- 放寬或修改已確認的門檻。
- 改變已確認的公式或單位。
- 修改被標示為「不要修改」的檔案。
- 直接推送到主分支。

## 確認點

| 確認點 | 階段 | 人要確認的內容 | 未確認時 |
|---|---|---|---|
| 範圍確認 | 需求 | 範圍內與範圍外的項目 | 停止，不進入規格 |
| 公式與單位確認 | 規格 | 每個計算公式、每個欄位的單位 | 標示為待定，不實作該部分 |
| 門檻確認 | 規格 | QA 的門檻數字 | 門檻為 `null`，QA 只出圖，不判定 |
| 架構確認 | 設計 | 模組與階段切分 | 停止，不進入實作 |
| 舊程式處置 | 實作 | 是否改動、是否還原 | 不改動舊程式 |
| 合併確認 | 交付 | PR 的審查結果 | 不合併 |

## 提問方式
- 一次只問與當前階段有關的問題。
- 每個問題附上建議，讓人可以直接回覆「同意建議」。
- 回覆之後，先確認理解，再動手。

## 中斷與回復
- 人可以在任何時候中斷。中斷後，Claude 不再繼續執行，直到人明確指示。
- 中斷前已完成的改動，要在回報中列出，並詢問是保留還是還原。
